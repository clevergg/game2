**Стратегия темы (решено после спора):** не «своя вселенная» и не «поздний клон брейнрота», а **проверенная механика + сменяемый data-driven мем-ростер**, старт на текущих мем-животных (tornado-squirrel / nihilistic-penguin энергия). Узнаваемость + деньги + устойчивость к смене трендов.

Работаем строго по фазам (см. бриф). В конце каждой фазы: отчёт в `docs/` + выжимка в чат + СТОП до «дальше».

## Стек (вектор, финализируется в Фазе 3)

- **Язык:** TypeScript strict, без `any`.
- **Рантайм/сборка:** Bun (dev, скрипты), сборка в статический `index.html` + ассеты для загрузки в консоль Yandex.
- **Рендер (кандидаты):** PixiJS (лёгкий 2D WebGL) или тонкий собственный Canvas2D-слой. Решение — Фаза 3.
- **Стейт:** без тяжёлых зависимостей в игровом цикле; UI-стейт возможно Zustand вне hot-path.
- **Платформа:** Yandex Games SDK через слой абстракции (игра работает и без SDK — оффлайн-устойчивость).

## Принципы (жёсткие)

- Игровая логика отделена от рендера и от платформенного SDK.
- Никаких аллокаций в игровом цикле; стабильный FPS на среднем мобильном железе.
- Тесты на чистую логику: экономика, генерация, правила.
- Тач-управление первично, десктоп вторичен.
- Быстрый первый запуск: агрессивный бюджет размера сборки (цель — единицы МБ, не потолок 100 МБ).
- Все строки — через словарь локализации (ru/en минимум, архитектура готова к tr). Никаких хардкодов текста в UI.
- Никаких внешних доменов/ссылок/сторонней аналитики/своей монетизации (причина отказа модерации).
- Только оригинальные мем-персонажи — без чужого IP (копирайт = отказ модерации).
- Ассеты генерируются кодом/скриптами (`scripts/`), каждый ассет собирается одной командой. Никаких заглушек.
